# HANDOFF: soup_tz

Состояние на 2026-11-12 (обновлено после проверки реплик и аварийного теста). Тестовое задание Soup «Full-Stack Engineer» (трекер экспериментов).
Код рабочий, все проверки зелёные, **ничего не закоммичено** (git init сделан, коммитов нет).

## Что где лежит

| файл | зачем |
|---|---|
| `DESIGN.md` | 1 страница дизайна (формат событий, повторные батчи, догонка после обрыва, изоляция), сдаётся |
| `NOTE.md` | записка ≤2 стр.: консистентность, изоляция, сбои, вердикт, «что удивило», ИИ; сдаётся |
| `README.md` | запуск, API, команды тестов |
| `app/soup/main.py` | роуты, middleware (логи без ключей, `no-store`), кэш запусков, тестовые хуки |
| `app/soup/ingest.py` | приём батча: блокировка строки run → дедуп по (key, step) → seq без пропусков → NOTIFY |
| `app/soup/stream.py` | SSE: LISTEN/NOTIFY как будильник + опрос раз в 2 с, курсор по seq, ping 5 с, перепроверка ключа |
| `app/soup/auth.py` | ключи (sha256 в БД, в логах только префикс), header или HttpOnly-cookie; запись только по header |
| `app/soup/static/run.html` | живая страница: проверка пропусков seq, watchdog 12 с, инкрементальный рендер |
| `tests/` | 11 тестов изоляции, 10 тестов скрытых сбоев, E2E на Playwright, `load_test.py`, `ui_scale_probe.py` |
| `scripts/` | `check_logs.sh` (утечка ключей в логи), `mutation_check.sh` (6 внесённых багов), `crash_test.py` (`kill -9` реплики и Postgres) |
| `docker-compose.replicas.yml`, `lb/nginx.conf` | 2 реплики приложения за nginx |
| `results/` | сырые выводы всего: pytest, E2E-отчёт + скриншот, нагрузка, мутации, логи |

## Как запустить и проверить

```bash
docker compose up -d --build --wait
```

```bash
docker compose run --rm tests
```

```bash
./scripts/check_logs.sh
```

```bash
./scripts/mutation_check.sh
```

```bash
docker compose run --rm tests python load_test.py --runs 50 --rate 10 --batch 10 --duration 60
```

Все тесты занимают около 65 с, мутации около 3 мин (пересобирают app, потом восстанавливают код).

Реплики и аварийный тест:

```bash
docker compose -f docker-compose.yml -f docker-compose.replicas.yml up -d --build --wait
```

```bash
uv run --python 3.12 --with httpx --with 'psycopg[binary]' scripts/crash_test.py
```
Admin-токен в compose: `dev-admin-token`. `SOUP_TEST_HOOKS=1` включает тестовые хуки, в проде его быть не должно.

## Известные ограничения (честно указаны в NOTE.md)

- Реплики проверены только в схеме «2 штуки + nginx» на одной машине; E2E-тест сам по себе ходит в один процесс.
- Нет rate-limit по проекту: шумный проект может замедлить чужие, а задержка становится побочным каналом.
- Изоляция держится на `project_id` в каждом запросе; RLS в Postgres нет.
- Открытый поток может пережить ротацию ключа максимум на 2 с; тихо умерший клиент видит устаревшие данные до 12 с, а сервер держит такого подписчика до таймаута TCP.
- NOTIFY берёт глобальную блокировку на коммите: потолок пропускной способности, не измерялся.
- WebSocket не реализован (только SSE).

## Вопросы на обсуждении: где ответ

- *Клиент был офлайн 30 с:* если обрыв явный, EventSource переподключается сам с `Last-Event-ID` и догоняет из БД; если тихий, watchdog через 12 с переподключает. Данные не теряются, видна только задержка. NOTE §1, §3.
- *Где дизайн слабее всего:* Postgres как узкое место при неbatched-записи, глобальная блокировка NOTIFY, блокировка записи на запуск (последовательная запись), нет performance-изоляции. NOTE §4–5.
- *Как узнать в проде, что событие потеряно:* seq без пропусков, клиент считает пропуски (счётчик на странице); на сервере сверять `last_seq` и `count(*)` по запуску; отправлять пропуски с клиента в мониторинг. NOTE §5.
